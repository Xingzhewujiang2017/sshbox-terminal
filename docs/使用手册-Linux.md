## 1. 这是什么

SSHBox 是一个 SSH 终端 + 实时监控客户端：连上 Linux 服务器后，除了终端，还能看 CPU/内存/磁盘/进程/时延曲线、回看历史、传文件、开端口转发、生成巡检报告。

**Linux 桌面版和 Windows 版的关系**：界面是同一套代码，功能一样。区别只在"外壳"——

| | Windows 版 | Linux 桌面版 |
|---|---|---|
| 外壳 | Tauri + 系统 WebView2 | Electron + 自带 Chromium |
| 体积 | 约 13 MB | 约 111 MB（含浏览器内核） |

**为什么 Linux 版要用 Electron**：国产化系统（openEuler / EulerOS 等）把 WebKitGTK 冻结在 2.38.2，而 Tauri 要求 ≥ 2.40，装不起来。Electron 自带浏览器内核，不依赖系统 WebKit，所以在这些系统上能跑。

**代价要说清楚**：包大了约 100 MB，这是"自带内核"换来的。

## 2. 系统要求

- x86_64 Linux 桌面（有图形界面）
- glibc ≥ 2.25（近几年的发行版都满足）
- 以下系统库（桌面环境通常自带）：

```
libgtk-3.so.0   libnss3.so   libgbm.so.1   libasound.so.2
libxkbcommon.so.0   libatk-1.0.so.0   libatk-bridge-2.0.so.0
libcups.so.2   libdrm.so.2   libxcomposite.so.1   libxdamage.so.1   libxrandr.so.2
```

启动脚本会自检，缺什么会直接打印出来。

**不需要**：不需要 WebKitGTK，不需要 libsoup，不需要 root。

## 3. 安装与启动

### 3.1 解压即用

```sh
tar xzf SSHBox-electron-spike-linux-x86_64.tar.gz
cd SSHBox-linux-x64
```

目录里有：`SSHBox`（主程序）、`start.sh`、`run.sh`、`install-desktop.sh`、`resources/`（前端与后端）。

### 3.2 两种启动方式

| 脚本 | 行为 | 什么时候用 |
|---|---|---|
| `./start.sh` | **后台启动**，日志写 `~/.config/sshbox/electron.log`，关掉终端也不退出 | 日常使用 |
| `./run.sh` | **前台启动**，占着终端，后端日志直接打在屏幕上 | 排查问题 |

### 3.3 装成桌面应用（推荐）

```sh
./install-desktop.sh
```

它会做两件事：

1. 写 `~/.local/share/applications/sshbox.desktop` —— 应用菜单里出现 **SSHBox**
2. 往 `~/Desktop`（或中文环境的 `~/桌面`）放一个图标，并标记为受信任（GNOME 不打这个标记，双击会被当成文本文件打开）

装完之后**双击图标启动**，不会弹终端窗口（桌面项的 `Terminal=false`）。

> 提示：图标里的路径是绝对路径。如果你把 `SSHBox-linux-x64` 目录挪了位置，需要重跑一次 `./install-desktop.sh`。

### 3.4 启动后发生了什么

主程序会拉起一个内置后端（`resources/sshbox-web`），它只监听 **127.0.0.1** 的随机端口，窗口再连到这个地址。所以：

- 不占固定端口，不会和你机器上其它服务冲突
- 外部访问不到（只绑本机回环）

## 4. 第一次启动：设置主密码

首次启动会弹一个对话框，标题是 **「设置主密码」**。

### 它是什么

主机密码要用它加密后才能存到硬盘。**主密码本身不落盘**——忘了只能删掉凭据文件重来。

### 怎么填

- 至少 6 位，需要输两次确认
- 点 **「设置」** 完成；点 **「以后再说」** 跳过

### 跳过会怎样

- 主机记录照常保存
- 但**密码不会持久化**：每次连接都要重新输，关掉程序就忘

### 加密细节（想了解的看）

| 项 | 实现 |
|---|---|
| 密钥派生 | PBKDF2-HMAC-SHA256，20 万轮 + 16 字节随机盐 |
| 加密 | AES-256-GCM，每次写盘换新 nonce |
| 落盘 | `~/.config/sshbox/credentials.enc`，权限 0600 |
| 文件内容 | 只有 salt / nonce / 密文，**没有主密码，也没有明文密码** |

之后每次启动会弹 **「解锁凭据保险箱」**，输一次主密码即可。同样可以点「以后再说」先跳过。

## 5. 添加主机并连接

1. 左侧主机列表点 **「+」** 新建
2. 填 **主机地址、端口（默认 22）、用户名**
3. 认证方式二选一：
   - **密码**：填密码，勾 **「保存密码（加密存储）」** 才会进保险箱
   - **密钥**：填私钥文件路径（目标机上真实存在的路径，如 `/home/you/.ssh/id_rsa`）
4. 保存 → 双击主机名连接

**首次连接会问主机密钥指纹**（`strict` 策略下），确认无误再信任。也可以给单台主机设成 `accept_any` 跳过校验（不建议，除非你清楚风险）。

## 6. 界面与终端

左侧是主机列表（可按分组折叠），中间是终端标签页，右侧可以拉出监控面板。

### 终端

- 支持 256 色、鼠标选中复制
- **Ctrl+F** 打开搜索框（在回滚缓冲里找，会显示「共 N 处」）
- 右键菜单：复制 / 粘贴 / 让 AI 解释选中内容

### 标签状态

标签上会显示 `重连 5s` / `重连中…`。**重连不会抢走你正在看的标签**——三个标签同时掉线时，界面会停在原处。

想立刻重试，点标签旁的 **「立即重试」**。

## 7. 监控面板

连上主机后打开监控面板，能看到：

| 区块 | 内容 |
|---|---|
| 系统信息 | 主机名、内核、发行版、CPU 型号、核心数 |
| 实时指标 | CPU、内存、磁盘读写、网络吞吐、进程数、负载 |
| 磁盘 | 各挂载点用量（虚拟文件系统会标「虚拟」，不计入合计） |
| 进程 | CPU/内存 Top N |
| 服务 | systemd 单元状态 |
| 硬件 | 温度、GPU 负载 |
| 时延 | 到**默认网关**的 RTT 与丢包 |

**采集是只读的**：只读 `/proc`、`/sys` 和命令输出，不改目标机任何东西。

默认 10 秒一次（设置里可调）。网络时延走慢通道，约 15 秒一档。

---

## 8. 历史回看

历史面板按时间范围查曲线：CPU / 内存 / 磁盘 / 网络 / 进程数 / 时延，支持多主机对比。

数据存在本机 `~/.config/sshbox/history.sqlite`，不上传任何地方。

可以导出 CSV / JSON 到本地目录。

## 9. 文件传输

双栏界面：左边本机、右边远端。

- 双击目录进入，`..` 返回上级
- 拖文件到另一栏即上传/下载（有断点续传）
- 进度条在底部，可取消

**注意**：本机这一侧读的是**运行 SSHBox 的这台机器**的文件，不是远端。

## 10. 端口转发

支持本地转发、远程转发，规则跟着主机走（导入导出会一起带走）。

- 可以给规则设「自动启动」，连接时自动拉起
- 启动失败会在界面上报原因（端口被占用 / 需要管理员权限等）

## 11. 一键巡检报告

选一台已连接的主机 → 生成报告。产出两个文件：

- `SSHBox-巡检报告-<主机名>-<时间>.html`（自包含，双击即看，不联网）
- 同名 `.md`（可再编辑）

报告内容：系统信息、资源水位、磁盘、Top 进程、服务状态、网络时延、异常发现。

### 「打开文件夹」和「定位 HTML」

两个按钮都会调系统文件管理器打开报告所在目录：

```
依次尝试 xdg-open → gio open → nautilus
```

如果三个命令都没有，会明确报错 **「打不开文件管理器：找不到 xdg-open / gio / nautilus」**（不会假装成功）。

## 12. AI 助手

### 先配一个接入点

设置 → AI 模型 → 新建接入点，填：

- 名称、协议（OpenAI 兼容 / Anthropic / Ollama）
- 接口地址、模型名
- API Key（写进保险箱，**不会回传界面，也不会出现在 settings.json**）

内置预设只有两个：**本地 Ollama**、**SiliconFlow**。其它服务用「新建接入点」自己加。

### 三个入口

1. 终端右键 → 解释选中的报错
2. 侧栏对话
3. 生成命令 —— **只把命令填进终端，不自动执行**，回车由你按

## 14. 日志与排障

### 两个日志文件

| 文件 | 内容 |
|---|---|
| `~/.config/sshbox/logs/sshbox-web.log` | **后端**：连接、认证、采集、命令失败（超 5MB 自动滚一份 `.1`） |
| `~/.config/sshbox/electron.log` | Electron 主进程 + 启动脚本输出 |

两个文件都过滤掉了第三方库的噪音（russh / zbus / keyring / hyper 等），只留能用的信号。

### 常见问题

**① 启动没反应 / 一闪而过**

```sh
cd SSHBox-linux-x64
./run.sh          # 前台跑，能看到错误
```

**② 提示缺库**

`run.sh` 会打印 `缺少系统库: libxxx.so`。把这一行发出来，会打包补上。

**③ 提示 sandbox 错误**

容器里 `chrome-sandbox` 没有 SUID root 权限。`start.sh` / `run.sh` 会**自动检测并加 `--no-sandbox`**；如果手工启动主程序，需要自己加。

**④ 连不上主机**

看 `sshbox-web.log` 里这几行：

```
[连接 x.x.x.x:22] TCP+握手完成，开始认证
[连接 x.x.x.x:22] 认证结果 success=true
[连接 x.x.x.x:22] 连接中断（读循环结束…）
```

- 停在「TCP+握手」→ 网络/端口不通
- 认证失败 → 用户名/密码/私钥
- 「连接中断」→ 连上了但被断开，这一行就是排查起点

**⑤ 忘记主密码**

```sh
rm ~/.config/sshbox/credentials.enc
```

主机记录不受影响，但已保存的密码全丢，需要重新输。

**⑥ 报告按钮点了没反应**

说明机器上找不到文件管理器命令。装一个即可（`xdg-utils` 提供 `xdg-open`）。

**⑦ 桌面图标双击变成文本**

GNOME 需要信任标记。重跑 `./install-desktop.sh`，它会给图标打 `metadata::trusted`。

## 15. 数据目录与备份

全部数据在 **`~/.config/sshbox`**（可用环境变量 `SSHBOX_HOME` 覆盖）：

```
hosts.json         主机列表（不含密码）
settings.json      设置
credentials.enc    密码保险箱（主密码加密）
history.sqlite     历史数据
known_hosts        已信任的主机密钥
logs/              日志
```

**备份**：整个目录拷走即可。**换机器**：拷过去，用同一个主密码解锁就能继续用。

## 16. 卸载

程序是绿色包，删目录即可：

```sh
pkill -f 'SSHBox-linux-x64'                       # 先停进程
rm -rf ~/SSHBox-linux-x64                         # 程序目录（按你实际解压位置）
rm -f ~/.local/share/applications/sshbox.desktop  # 应用菜单项
rm -f ~/Desktop/sshbox.desktop ~/桌面/sshbox.desktop
rm -rf ~/.config/sshbox                           # 数据（可选，删了就没了）
```

只删程序、保留数据的话，新版装回来会**直接沿用**原来的主机和保险箱。

## 17. 已知限制

| 项 | 现状 |
|---|---|
| 本地服务鉴权 | 无。只监听 127.0.0.1，但**本机其它进程能访问这个端口并用已解锁的凭据** |
| 主密码忘记 | 只能删 `credentials.enc` 重来（"不落盘"的必然代价） |
| 输入法（fcitx）、高 DPI、字体回退 | 未在国产化目标机上逐项实测 |
| 「定位报告」 | 依赖系统文件管理器命令，没有会报错 |
| 体积 | 约 111 MB（自带 Chromium 的代价） |
