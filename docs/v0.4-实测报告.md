# SSHBox v0.4 实测报告

> 版本 0.4.0 ｜ 2026-09-19 ｜ 全部结论来自真机（WSL Ubuntu 22.04 / OpenSSH 8.9p1）跑出来的结果，不是"应该能行"。
> 测试机：`root@127.0.0.1:22`（WSL2 Ubuntu），宿主机 Windows 11。

## 一句话结论

v0.4 的六项功能（SFTP 双栏、断点续传、本地转发、远程转发、快捷命令、多会话广播、标签拖拽排序）
全部通过端到端实测；过程中发现并修掉 **6 个真 bug**，其中 1 个（远程转发）会让功能完全不可用。
后端 66 个单元测试全绿，另有 3 个 live 测试直连真机跑完整传输。

## 途中修掉的真 bug

| 症状 | 根因 | 修法 |
|------|------|------|
| **-R 远端能连上但立刻 `Connection reset by peer`** | `tcpip_forward` 返回的是"服务端回复里的端口"，而 RFC 4254 规定：客户端请求了非 0 端口时服务端回复**不带端口**（russh 返回 0）。于是路由表键成了 `(host, 0)`，远端真连 13400 时查表必然落空 → 拒绝 | 新增纯函数 `resolve_listen_port(请求值, 回复值)`：请求非 0 用请求值，请求 0 才用回复值。配套单测钉住 RFC 行为 |
| -R 规则面板显示 `监听 127.0.0.1:0` | 同一个根因的另一面：运行态回传的 `actual_port` 也是 0，盖掉了配置值 | 同上修复后显示 `127.0.0.1:13400` |
| 本地路径显示成 `\\?\C:\Users\Z` | `std::fs::canonicalize` 在 Windows 上带扩展长度前缀 | 展示前剥掉 `\\?\` 前缀 |
| 传输完成后面板列表不刷新 | 上传结束后没重新拉远端目录 | 任务完成回调里触发列表刷新 |
| `sftp_forget` 编译不过 | Tauri 约束：async 命令带引用参数必须返回 `Result` | 改成返回 `Result<(), SshboxError>` |
| 拖放上传拿不到路径 | 事件 payload 字段名用错 | 按 Tauri v2 的 `paths` 字段取值 |

### 一处值得记的设计

传输核心**刻意不绑定 `AppHandle`**，进度通过 sink 抽象往外抛。代价是多一层泛型，
好处是能在 live 测试里对着真机跑完整传输（连进度、取消、续传都能断言），
不必启动 GUI —— 这次 4MB 文件的逐字节一致性就是这么验的。

## 还没做 / 还没验（不粉饰）

1. **OS 文件拖入上传**：内部拖拽走通了，但从资源管理器往窗口里拖文件**没验**——合成事件造不出真实的 OS 拖放，
   需要人手拖一次。代码路径已接（Tauri `drag-drop` 事件 → 上传队列）。
2. **-R + GatewayPorts**：远端监听 `0.0.0.0` 的场景没验，只验了 `127.0.0.1`。
3. **安装包**：0.4.0 的 NSIS 打包本次开始跑，尚未产出验收（0.3.1 的包是好的）。
4. **浅色皮肤下的新面板**：v0.4 新增的 SFTP / 转发面板在浅色主题下没逐个看过配色。
