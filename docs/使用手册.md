# SSHBox 使用手册

**版本 0.5.0** · SSH 终端 + 虚拟机实时监控 + AI 助手 · Windows 桌面应用（MIT 开源）

SSHBox 是一个把「连服务器」和「看服务器」放在同一个窗口里的工具：左边是主机列表，
右边是多标签 SSH 终端，随时能展开监控、文件传输、端口转发和快捷命令面板，
不用再开一堆 PuTTY / WinSCP / 另一个终端。

## 1. 安装

### 系统要求

- Windows 10 / 11（64 位）
- 目标机器需开启 SSH 服务（Linux 默认就有；Windows 需装 OpenSSH Server）

### 安装步骤

1. 双击 `SSHBox_0.4.0_x64-setup.exe`（安装包 3.7MB）。
2. 若安装程序提示缺少 **WebView2 运行时**（干净系统 / 离线机器常见），
   先运行随附的 `MicrosoftEdgeWebView2RuntimeInstallerX64.exe`（203MB 离线包），
   装完再装 SSHBox。
   > WebView2 是 Windows 自带的浏览器内核组件，Win11 通常已内置；
   > 在线机器也可以让安装程序自动联网获取。
3. 安装完成后从开始菜单启动。

### 绿色版

不想安装可以用绿色版：`sshbox.exe`（10.6MB）直接双击运行，配置同样存在
用户目录下（见 [第 15 节](#15-数据与文件位置)）。

## 2. 第一次连接

点左上角 **＋ 新建连接**（或按 `Ctrl+T`），填写。**带红色 `*` 的是必填项**
（主机地址、用户名、密码认证时的密码），端口必须是 1–65535 的整数 ——
填了非数字或留空时「保存」按钮会保持灰色，不会让你存进一条连不上的记录。

| 字段 | 说明 |
|---|---|
| 名称 | 显示在列表里的名字，如「生产 Web」；留空时用主机地址当名字 |
| 主机地址 `*` | IP 或域名 |
| 端口 | 默认 22，范围 1–65535 |
| 用户名 `*` | 登录账号 |
| 认证方式 | 密码 / 私钥 |
| 密码 `*` | 勾选 **保存到系统凭据管理器** 后会加密存进 Windows 凭据管理器，明文不落盘。**新建时默认勾选**，所以填一次以后双击就能直接连 |
| 私钥文件路径 | 私钥认证时填写；加密私钥在连接时会提示输入口令（口令也可选择保存） |
| 主机密钥校验 | **严格（推荐）**：首次连接记住指纹，之后变了就报警；也可选跳过校验 |
| 分组 | 下拉列出所有已有分组，也可以直接输入一个新分组名 |
| 备注 | 可选 |

点保存后，在左侧列表 **双击** 主机即可连接；右键还有
编辑 / 复制一份 / 删除 / 设置。

### 主机列表的分组

- 分组标题左边有个 `⠿` 把手，**按住分组标题上下拖动**可以调整分组顺序，
  顺序会存进 `hosts.json`，下次打开还是这个顺序。
- 分组标题点一下展开 / 收起；**默认只展开第一个分组**，其余收起 ——
  分组多了不至于铺满整个侧栏。
- 搜索框同时匹配主机名、地址、用户名和分组名。

**首次连接会弹主机密钥确认框** —— 这是防止中间人攻击的正常步骤，
核对指纹后点接受即可，之后该主机会被记住（存在 `known_hosts`）。
如果哪天指纹变了（重装系统、换了机器），会再次报警，**别习惯性点接受**，
先确认是不是你自己动过。

连接成功后会开一个新标签页，标签上显示主机名，标题栏有会话状态。
断线后如果开了自动重连（默认开），会按退避策略自动重试，最多 3 次。

## 4. 终端

### 右键菜单（复制粘贴 + AI）

在终端里右键弹出菜单。**复制粘贴是基本盘，永远排在最上面**；AI 是增强，永远在
分隔线下面，两者不抢位置：

```
复制            Ctrl+Shift+C       ← 没有选中时置灰并说明原因
粘贴            Ctrl+Shift+V
────────────────────────────
解释这段（AI）                     ← 没选中时解释最近的输出
用自然语言生成命令…（AI）
────────────────────────────
全选 / 清屏
────────────────────────────
取消
```

- 菜单作用于**你右键的那块终端**（多标签下不会串到别的会话）。
- 粘贴**不自动回车** —— 命令先出现在输入行，你确认后再按回车。
- `Ctrl+C` **仍然是中断信号**，没有被复制抢走（实测：能打断 `sleep 30`）。
  终端里的复制/粘贴别名是 `Ctrl+Shift+C` / `Ctrl+Shift+V`。
- 「清屏」只清本地的回滚缓冲和显示，不会去动远端 shell 的状态。

- **多标签**：每台连接一个标签，点标签切换；`Ctrl+W` 关闭当前标签（可在设置里
  开启关闭前二次确认，防止误关掉正在跑任务的会话）。
- **标签排序**：按住标签左右拖动即可调整顺序。
- **广播输入**（`Ctrl+Shift+B`）：打开后，你在一个终端里敲的命令会同时发到
  所有已连接会话 —— 批量在多台机器上执行同一条命令时用。**开启时标签栏有
  明显提示，按 `Esc` 立刻退出广播**（这是最容易误操作的模式，所以给了
  最快的退出键）。
- **滚动回看**：终端保留历史输出，可用鼠标滚轮 / 滚动条回看。
- **复制粘贴**：鼠标选中要复制的内容，`Ctrl+C` 复制、`Ctrl+V` 粘贴，走系统剪贴板。
  粘贴到终端**不会自动回车**，可以先改完命令再按回车执行。

## 5. 监控面板

连接成功后监控面板自动开始采集（采样间隔默认 2 秒，可在设置里改）。
面板上的卡片：

| 卡片 | 内容 |
|---|---|
| 系统 | 发行版、内核、运行时长 |
| CPU | 使用率 + 负载 |
| 内存 | 已用 / 总量 |
| 磁盘 | 各挂载点使用率 |
| 网络 | 各网卡收发速率；到默认网关的**时延/丢包趋势图**（双轴：左 ms / 右 %，横轴时间刻度，悬停显示 时延 / 丢包 数值；每 15 秒一档，近 12 分钟，采到默认网关才有曲线） |
| 磁盘 IO | 各设备读写速率 |
| 温度与 GPU | 传感器温度、风扇、GPU（有才显示） |
| 进程 Top | 按 CPU 排序的进程表（默认取前 12 个，可在面板上切到 50 或全部） |
| 服务与端口 | systemd 失败单元 / 监听端口 / docker 容器 |

- 面板顶部有 **暂停采集 / 继续采集** 和 **立即采集一次**；
  暂停时面板会明确标注「数据不再更新」，不会让你看着旧数字以为是实时。
- 折线图保留最近 **150 个采样点**，所以窗口时长随采样间隔变化：
  间隔 2 秒时约 5 分钟，间隔 5 秒时约 12.5 分钟（面板标题会直接写出「近 N 分钟」）。
- **不可见的标签页会自动降频到 5 倍间隔**以省带宽，所以后台会话的数字
  变化慢是正常设计，不是卡了。
- **切换标签时面板跟着切**：面板始终显示当前标签那台主机的数据，
  换标签、关标签都会立刻重建，不会残留上一台的曲线。
- 环形图和折线图是**同一份数据**（环形是当前瞬时值，折线是它的历史），
  显示精度也一致：低于 10% 保留一位小数，避免 0.3% 被圆成 0% 看着像没数据。

### 长列表怎么翻

网络、磁盘、磁盘 IO、进程、端口这五处都可能很长，统一按 **每页 10 条**分页，
分页条在列表下方：`‹ 1 / 3 ›` 翻页，**「全部」**一键铺开、再点「收起分页」回到分页。

- 进程表默认只取 CPU 前 12 个（面板上「取前 12 / 50 / 全部」可切换）。
  选「全部」会取回所有进程，列表仍按 10 条一页显示 —— 表头写着「共 N 个」，
  和列表条数对不上时就是还没取全。
- 端口默认也是 10 个一页，需要看完整监听列表就点「全部」。

### 采集会占用目标机多少资源

采集脚本**只读** `/proc`、`/sys` 和若干命令输出，不往目标机写任何东西、不改配置、
不装包。实测（Ubuntu 22.04，16 核，28 个进程）：

| 采集 | 频率 | 耗时 | CPU 时间 | 占单核 |
|---|---|---|---|---|
| 指标（CPU/内存/网络/磁盘/进程） | 2 秒 | 约 20 ms | 约 10 ms | 约 0.5% |
| 服务/端口/温度/时延 | 15 秒 | 约 125 ms + ping 约 1 秒 | 约 30 ms | 约 0.2% |
| 一键巡检报告 | 手动触发 | 两次指标 + 一次慢采集 | 约 0.2 秒（一次性） | — |

客户端自身在监控中占用约 0.0%（20 秒内累计 CPU 时间为 0.00 秒）。采样间隔可在
设置里调大，占用线性下降。

两点如实说明：一是进程表那一段的开销随**进程数**线性增长，上表是 28 个进程的机器；
二是 ping 那一段有约 1 秒的 wall time（在等回包，几乎不吃 CPU），所以它放在 15 秒
的慢节奏里，而不是 2 秒的快循环 —— 否则两次采集会互相打架。

### 环回网卡为什么不显示

`lo`、`loopback0` 这类回环接口不出现在网络卡里 —— 它们是本机内部通信，
不含真实网络流量（如果你连的是 `127.0.0.1`，回环上跑的其实是你自己这条 SSH 连接）。
判定按接口类型而不是名字，所以 WSL 里那个叫 `loopback0` 的环回同样会被排除。

### 阈值告警

在设置里打开「阈值告警」后，CPU / 内存 / 磁盘 超过阈值（默认 90% / 90% / 90%）
会触发**系统通知**并在界面标红。这台机器上当前设置是内存 80%。

## 6. 历史回看

监控数据会落盘到本地 SQLite（默认开），所以**断线之后还能回看**：

- 历史采样间隔默认 2 秒，保留天数默认 30 天，过期自动清理。
- 打开「历史回看」面板，可选时间范围、看**聚合**曲线或**原始**点。
- 支持 **导出 CSV** 和 **打开文件夹**（导出的文件直接定位到资源管理器）。
- 时间范围有 1 小时 / 6 小时 / 24 小时 / 7 天 / 30 天 / 全部 / 自定义。

**窗口比数据长时会明确告诉你**：选「30 天」而库里只有两天数据时，曲线会平贴
底部（主机本来就空闲），看着像没查到东西。面板这时会在图上方给一条黄色提示，
写明**窗口内实际有数据的时段和占比**，例如：

> 窗口内实际有数据的时段：2026-09-19 12:48 → 2026-09-20 10:24（21.6 小时，占窗口约 3%）

想改保留天数或间隔，去 设置 → 常规 → 历史落盘。

## 7. 多主机总览

「总览」面板把所有主机放在一张表里：

- 已连接的会话显示**实时数据**（复用已有连接，不额外建连）。
- 未连接的主机可以勾选 **包含离线（历史最后状态）**，显示它最后一次采样的
  数据，并且**带时间戳**（如「7 分钟前」），避免把旧数字当成当前值。

### 分组视角（集群测试）

顶部有**分组下拉**：全部主机 / 各分组 / 未分组。选一个组后：

- 状态条变成**组级汇总**：组内在线 N/M 台、最忙 / 最闲主机（按 CPU），
  告警、陈旧、离线都只按组内统计；
- 行列表只剩组内主机，按需排序（按 CPU / 内存 / 磁盘 / 负载 / 状态）；
- 下方出现**组内历史对比**：每台主机一格的小曲线（CPU 实线 + 内存虚线），
  谁掉队一眼可见；窗口可切 1 小时 / 24 小时 / 7 天，切换即时重查；
- 对比的**指标可切换**：CPU/内存、网络（收实线/发虚线）、磁盘（读/写）、
  负载、时延/丢包（时延实线/丢包虚线，每 15 秒一档，测到默认网关才有）。

说明：组内历史对比显示的是**已连接会话**的历史（本版范围）；没有实时数据的
主机按「历史最后状态 + 年龄」显示。每格曲线是自绘 SVG，几十台也不卡。

- 支持按 CPU / 内存 / 状态 / 名称排序，点「切到」可直接跳到对应会话标签。
- 主视图可在**表格 / 卡片**之间切换：卡片视图每台一块（状态灯 + CPU/内存/磁盘
  条 + 网络/负载/进程 + 切到/连接按钮），组内多台时一眼扫完。
- 卡片下方还有**实时趋势图**（60 点滚动窗口，随事件更新）：蓝实线=CPU、
  绿虚线=内存、靛实线=时延（ms）、红点线=丢包（%），四条同时显示。

> v0.6.2 起故障注入已移入「演练台」（见下节 7.x），总览不再承载注入入口。
> 注入功能本体（tc netem、网卡自动探测、立即执行/仅等待、到期自动恢复、
> 清除规则）与**环境限制**（目标机需 `tc` 且内核可加载 `sch_netem`；
> WSL2 微软内核默认无此模块，执行报 `Specified qdisc kind is unknown`，
> 可用 `modprobe sch_netem` 确认）在演练台内原样生效。

### 故障演练台（7.x · v0.6.2）

工具栏「**演练台**」—— 单机/集群故障测试专用界面，**全程不跳页**：

- **分组下拉 + 主机列表**：顶栏下拉选「全部 / 分组 / 未分组」，列表显示
  **主机名称 + IP** + 在线状态；**离线主机也在列表里**——勾选或双击即建立会话
  （连接成功后自动勾选，趋势图随之出现）。**双击名称或点「终端 ▸」**，
  在演练台内直接展开该主机的终端（**可交互输入**，同真实终端；演练台不关）。
- **底部趋势图**：每台勾选主机两块 ECharts 大图（同监控平台风格）——
  CPU/内存一张（0-100 轴）、时延/丢包一张（左 ms 右 %，悬停显示数值）；
  数据 **3s 一档**（注入后 3 秒见曲线跳），窗口可切 **近3分 / 近15分 / 本次**
  （本次上限约 2 小时）；注入时刻在时延图上画黄虚线标记。
- **故障注入**：类型（时延/丢包/闪断/清除）。**网卡自动**模式会**先逐台
  探测默认路由出接口**，确认弹窗里每台显示接口名（如 `[eth1]`）、命令按主机
  各自生成 —— 多台网卡不同也不串；**手动**模式在**每台主机的行内**各自填网卡
  （不是全统一一个）。需要 root 或免密 sudo：命令自动带权限适配（非 root 时
  自动改用 `sudo tc`，两者都没有会明确报错而不是静默失败）。注入提示 25 秒
  无效果会红字说明。到期自动恢复；「生成并填入终端」后可选「⚠ 立即执行」
  （不切页）或「仅等待」。**清除**命令会回显"已清除该网卡上的规则"并显示
  当前网卡队列（一眼确认清没清干净）。
- **命令/脚本就地执行**：输入单条命令或多行脚本，勾选多台 → 「并行执行到 N 台」
  → 确认一次 → 每台一个输出块（stdout 尾部 + exit code + 耗时）。走只读
  exec 通道（non-interactive、带超时默认 60s）：`top`/`vim` 这类交互命令
  用列表里的「终端 ▸」展开跑。
- **导出 CSV**（工具栏「导出 CSV」）：勾选主机导出**两份**到
  `%APPDATA%\sshbox\exports\lab\` —— 采样数据（host,time,cpu,mem,时延,丢包,
  注入类型）+ 注入事件（host,time,event,kind,恢复时间,说明），**每台注入一次
  就记一条**（4 台注入必 4 条，含失败原因）；导出成功右上角**弹提示并显示
  文件路径**，Excel 可直接打开。
- 演练台里展开的终端同样支持**右键菜单（复制选中 / 粘贴 / 解释这段）**，
  以及 `Ctrl+Shift+C` / `Ctrl+Shift+V`。展开终端时自动补一次回车刷新提示符。
- 演练台是**二级页面**（不是弹层）：打开时主工作区（终端/监控）整体隐藏，不重叠、
  不挤占；关闭后回到主界面。打开时会自动收起监控面板。

- **注入未生效会自动提示**：注入后 25 秒内时延/丢包曲线无变化，注入区会红字
  提示"注入疑似未生效（目标机可能缺少 sch_netem 内核模块）"—— 不用对着
  平线猜。WSL2 微软内核就是典型（`wsl --update` 若可用可尝试换新内核，
  否则请用真实 Linux 目标机测注入）。

诚实说明：3s 高采对每台目标跑一次 `ping -c10`（10 包统计丢包率，比单包准，
丢包显示再做最近 3 次滑动平均，注入 10% 不再 0/100 乱跳）；10 台内无感
（实测），20 台以上建议别长时间开着重负载演练。

## 8. 文件传输（SFTP）

按 `Ctrl+Shift+F` 或点工具栏打开。左右两栏分别是**本地**和**远端**：

| 操作 | 做法 |
|---|---|
| 上传 | 选中本地文件 → 「上传选中项到远端当前目录」 |
| 下载 | 选中远端文件 → 「下载选中项到本地当前目录」 |
| 拖放上传 | **直接把文件从资源管理器拖进窗口**（见下） |
| 新建目录 | 远端栏的「新建目录」 |
| 改名 / 删除 | 右键或按钮，删除有二次确认（列出待删项） |
| 上一级 / 回到主目录 | 目录栏的 `..` 和「回到主目录」 |
| 刷新 | `F5` |
| 关闭 | `Esc` |

**大文件断点续传**：传输队列里中断的任务可以「续传」；目标已存在时会问
**覆盖 / 跳过**。队列显示进度和状态，可取消。

### 拖放上传的落点规则

- **SFTP 面板开着** → 文件上传到**远端当前目录**（就是右栏正在看的目录）。
- **SFTP 面板关着** → 文件上传到远端的 `~/sshbox-uploads/`，
  并把上传后的远端路径自动填到终端里（带引号，路径有空格或中文也不会断）。
- 拖放**需要有已连接的会话**，没有会话时拖入不会发生任何事（静默忽略）。

## 9. 端口转发

按 `Ctrl+Shift+T` 打开。支持两种方向：

| 类型 | 含义 | 典型用途 |
|---|---|---|
| 本地转发（-L） | 本机某端口 → 远端某地址 | 本机浏览器访问远端内网服务 |
| 远程转发（-R） | 远端某端口 → 本机某地址 | 让远端机器访问你本机的服务 |

填写：类型、监听地址 / 端口、目标地址 / 端口、备注。
监听端口填 **0** 表示让系统自动分配。规则可设 **自动启动**，
连接后自动生效，运行中的规则显示状态，可停止 / 编辑 / 删除。

> **注意**：远程转发（-R）如果监听地址填了 `0.0.0.0`，界面会提示：
> 远端 sshd 默认 `GatewayPorts no`，实际只会监听回环地址，
> 也就是**只有远端那台机器自己能连**。要让外部连上，得在远端的
> `sshd_config` 里设 `GatewayPorts yes`。

## 10. 快捷命令

终端上方的一条按钮带（`Ctrl+Shift+P` 展开 / 收起），点一下就把命令送进终端。
默认三条：**磁盘**（`df -h`）、**内存**（`free -h`）、**CPU Top**
（`ps aux --sort=-%cpu | head -15`）。

在 设置 → 常规 里可以增删改，命令里支持变量：

- `{host}`、`{user}`、`{port}` —— 会替换成当前主机的对应值，
  于是同一条按钮在不同机器上能生成不同的命令。

每条可以设「只填入不执行」（不自动回车），方便先改参数再跑。

## 11. AI 助手

AI 助手能读当前会话的主机背景和终端最近的输出，用来**解释报错**、**把中文需求变成命令**，
或者就着这台机器聊天。它**不会自己执行任何命令**。

### 先配一个模型

设置 → **AI 模型**。内置三个预设，填你要用的那个就行：

| 预设 | 地址 | 需要密钥 | 说明 |
|---|---|---|---|
| 本地 Ollama | `http://127.0.0.1:11434/v1` | 否 | 先 `ollama pull qwen2.5:7b` 拉个模型；本机跑、不出网，慢一些 |
| SiliconFlow | `https://api.siliconflow.cn/v1` | 是 | 国内可直连 |
| aiaaa.cc | `https://aiaaa.cc/v1` | 是 | 也可用于其它 OpenAI 兼容服务 |

- 点接入点的**编辑**填 API 密钥 → **保存**。
- **密钥存在 Windows 凭据管理器里**（条目 `ai:<接入点id>`），不写进 `settings.json`，
  界面上只显示「已存密钥」。点「删密钥」可单独清掉。
- 点**测试连接**会真发一条极短请求，一次测出密钥、地址、模型名三件事对不对
  （结果带耗时和模型回显）。
- 点**使用**把它设为当前模型。**没有选中任何接入点时 AI 入口是禁用的**，
  鼠标悬停会说明原因。

### 自定义接入点

「＋ 添加自定义接入点」可以接任何兼容服务，三种协议都支持：

| 协议 | 适用 | 地址怎么写 |
|---|---|---|
| OpenAI 兼容 | OpenAI / DeepSeek / 硅基流动 / Ollama / vLLM / one-api 等 | 填到 `/v1` 为止，如 `https://api.deepseek.com/v1` |
| Anthropic | Claude 官方 API | `https://api.anthropic.com/v1` |
| Google Gemini | Gemini 官方 API | `https://generativelanguage.googleapis.com/v1beta` |

模型名按服务商文档填（如 `deepseek-chat`、`claude-3-5-sonnet-latest`、`gemini-2.0-flash`）。
误删了预设可以点「补齐预设」找回。

### 三个入口

| 入口 | 怎么用 |
|---|---|
| 终端右键 | 选中一段报错 → 右键 →「解释这段」；或「用自然语言生成命令…」 |
| `Ctrl+Shift+I` | 打开 / 收起 AI 侧栏 |
| 工具栏「AI」 | 同上；侧栏里可在**对话**和**生成命令**两种模式间切换 |

侧栏提问会带上**当前会话的主机背景**和**终端最近的输出**（按预算裁剪，保留头尾），
所以「刚才那条命令为什么失败」这种指着终端问的话可以直接问。

### 生成命令：只填入，不执行

AI 给出的命令有两条路进终端：

- 点命令框下面的**「插入终端」**
- 或者**直接双击命令框**
- **对话/解释回复里的命令行**（整行是命令的，绿底高亮）每行右侧也有一个
  「**插入**」小按钮，点它把这一行填进终端（回车由你按）。

两种都**只把命令填进终端、不会回车**，执行与否由你按回车决定 —— 模型有可能给出
`rm` 这类危险命令，这一步是最后一道闸。

命令还会**填回它被生成时的那台主机**：如果你切到别的标签上双击历史命令，应用会先切回
那台主机的标签再填入，不会把 A 机的命令贴到 B 机；那台会话已经关了则会明确提示，
不会随便找个终端填进去。

### 安全边界（重要）

- AI **不会自动执行任何命令**，也不会自己改配置。
- 密钥只进系统凭据管理器，明文不回传界面、不落配置文件。
- 「解释这段」会把**终端最近的输出**发给模型 —— 那段里若有敏感信息（密码、token、
  内网地址），它就会出网。用本地 Ollama 则不出网。

## 12. 一键巡检报告

工具栏点**「报告」**，先弹一个小菜单选时间范围（最近 1 小时 / 24 小时 / 7 天），
几秒后右下角出现一张卡片，报告同时写到桌面：

- `SSHBox-巡检报告-<主机名>-<时间戳>.md` —— Markdown，方便贴进工单
- `SSHBox-巡检报告-<主机名>-<时间戳>.html` —— 自包含网页，双击就能看

报告里**内嵌趋势图**（CPU、内存、网络收发、磁盘读写、负载共五张），默认显示最近
**24 小时**；页面顶部可切到 1 小时 / 7 天，或选自定义起止时间。切换是**纯前端重绘**，
不重新生成报告，也不联网 —— 图表用内联 SVG 手绘，不引任何 CDN，整份 HTML 只有
几十 KB，当附件发出去、断网打开都正常。生成时选的范围决定各小节的统计窗口与
AI 结论看到的跨度；趋势图在 HTML 里仍可切到任意档。

趋势图**多两张「时延 / 丢包」曲线**（同时间轴，随窗口联动）：数据来自连通期间
每 15 秒一次的对默认网关 ping。刚升级时没有历史，图上会注明「连通期间每 15 秒
自动记录」，跑一会儿就有了。

「网络」小节给出当前收发速率与窗口内均值/峰值，并附**链路质量**：到默认网关的
平均时延、抖动与丢包率（拿不到网关或没装 ping 时这一块整块不显示，不会编数字）。
「进程」小节按 CPU 和内存各列前 8 个进程。

内容：主机与系统信息、CPU / 内存 / Swap / 磁盘 / 负载 / 温度、监听端口、失败的
systemd 单元等，并按规则给出**异常结论**（严重 / 警告）。数字与监控面板**同源**
（走同一条采集与解析路径），不会出现两处对不上。

配好模型后，「报告」还会附一段 **AI 结论**（把规则判定交给模型用中文讲一遍并给出
处置建议）。可在 设置 → AI 模型 里一键关掉，关掉后报告完全由规则生成。
**AI 结论失败不影响报告本身**，卡片上会写明原因。

卡片上的「打开文件夹」定位到报告，「定位 HTML」单独打开网页版。

## 13. 设置详解

### 常规

| 设置项 | 默认 | 说明 |
|---|---|---|
| 主题 | 深色 | 深色 / 浅色 / 跟随系统 |
| 监控采样间隔（秒） | 2 | 预设 1/2/5/10，也可**自定义 1-3600**；不可见标签页自动降频到 5 倍间隔 |
| 启用实时监控面板 | 开 | 关掉则不采集，省资源 |
| 断线后自动重连 | 开 | 退避重试，最大重试次数默认 3 |
| 关闭已连接的标签页时二次确认 | 开 | 防误关 |
| 阈值告警 | 开 | CPU / 内存 / 磁盘 阈值，默认 90 / 90 / 90 % |
| 历史落盘 | 开 | 采样间隔默认 2 秒，保留默认 30 天 |
| 重启监控任务 | — | 改完采样相关设置后点它立即生效 |

### AI 模型

**最大输出（max_tokens）**默认 4096。注意**推理模型的"思考过程"也算在这份额度里**：
额度太小就会出现"思考写满了、正文一个字没留下"。真遇到时界面会直接告诉你当前值和
建议值（例如"当前 1024 个 token，建议改成 4096 或更大"），照它改就行 —— 设置 →
AI 模型 → 最大输出，上限 32000。非推理模型用不着这么大，但留足没有坏处。

**思考过程自动剥离**：自建模型（如 qwen3.6-27B 这类把思考写进正文字段的服务）聊
天、生成命令、报告 AI 结论时，带标记的思考内容会自动剥离开来，折叠在「思考过程」
栏里（可展开），正文只留答案 —— 不用改服务端配置。

见 [第 11 节](#11-ai-助手)。要点：三个预设（本地 Ollama / SiliconFlow / aiaaa.cc）＋
自定义接入点、支持 OpenAI 兼容 / Anthropic / Gemini 三种协议、密钥进系统凭据管理器、
「测试连接」真发一条请求验证、以及「报告里附 AI 结论」的开关。

### 导入导出

- **导出到文件**：把主机列表导出成 JSON；可选「同时导出密码」——
  那是**明文 JSON，注意保管**。
- **从文件导入**：合并导入，**不覆盖同 id 的已有主机**，换机器迁移很方便。

### 关于

显示版本、配置目录、以及各个数据文件的位置（主机列表 / 设置 / known_hosts），
排障时直接照着路径找文件。

## 16. 常见问题

**连不上，提示「无法连接到 x.x.x.x:22」**
先确认目标机 sshd 在跑、端口通。如果目标是本机的 WSL，
WSL2 空闲会自动关机，端口转发随之消失 —— 在 WSL 里跑个
`wsl.exe -d Ubuntu -e sh -c "while true; do sleep 3600; done"` 保活即可。

**提示「认证被服务器拒绝」**
密码错或认证方式不对。先在命令行用同一个密码验证：
`sshpass -p '密码' ssh -o PreferredAuthentications=password root@主机 whoami`。
如果命令行能过，再看应用里是不是密码框残留了旧值（重启应用即可清空）。
服务端原因可以看远端 `/var/log/auth.log`。

**主机密钥变了，报警了怎么办**
先确认是不是你自己重装 / 迁移了机器。是的话，删掉 `known_hosts` 里对应条目
（设置 → 关于 能看到文件位置）后重连；不是的话，别接受。

**窗口一片白**
通常不是崩溃，是前端资源没打包好。重新构建 / 重装一次即可；
开发场景下确认 `dist/assets/` 非空。

**拖文件进窗口没反应**
需要**有已连接的会话**；没会话时是静默忽略的。另外面板开着和关着，
上传落点不同（见 [第 8 节](#8-文件传输sftp)）。

**进程表看不到别人的进程 / 容器卡说没权限**
远端 `/proc` 挂了 `hidepid=2` 时看不到其他用户的进程；
docker 容器卡需要登录用户在 `docker` 组里。界面上的提示文案对这两种情况
都是如实描述的，不是应用坏了。

**收不到阈值告警通知**
确认 设置 → 常规 → 阈值告警 是开的，且 Windows 通知权限允许 SSHBox 发送通知。

**关了窗口再打开，历史数据还在吗**
在。历史落盘在 SQLite 里，重启后打开「历史回看」面板即可回看，
不需要重新连接主机。

**选了「30 天」但图上几乎是空的**
正常，看你库里到底有多少数据。面板会给出「窗口内实际有数据的时段」提示：
如果只覆盖几小时，那就是数据本来就只有这么多（保留期默认 30 天，
但只有应用运行、会话连着的时候才会落盘）。曲线平贴底部也多半是主机真的空闲，
不是没查到。

**网络卡里为什么没有 lo / loopback0**
回环接口是本机内部通信，不算真实网络流量，所以被排除（判定按接口类型，
WSL 那个叫 `loopback0` 的也一样）。见 [第 5 节](#5-监控面板)。

**双击主机又让我输密码**
说明这台机器名下没有可用凭据。常见两种情况：一是当初建主机时没勾
「保存到系统凭据管理器」（现在新建默认勾选）；二是**保存的密码已经过期**
（远端改过密码），此时会认证失败再弹框，输一次新密码就会覆盖旧的。
输完如果还连不上，先按上面「认证被服务器拒绝」那一条在命令行验证密码。

**AI 回答是空的 / 报错怎么看**
先看日志（位置见上一节），每次请求都有两行：`[ai] 请求 req=… kind=… 端点=… 密钥=… 消息=N 条`
和 `[ai] 完成 …ms，回答 N 字`。据此能分清是密钥、地址、模型名、超时，还是模型真没说话。

**本地 Ollama 回答很慢或很敷衍**
7B 小模型在本机跑本来就慢（几十秒正常），能力也明显弱于云端。先 `ollama pull`
一个更大的模型，再到 设置 → AI 模型 把模型名改掉。

**AI 入口是灰的 / 点不动**
说明没选中接入点或没填密钥 —— 鼠标悬停会显示具体原因。去 设置 → AI 模型 填好密钥后点「使用」。

**密钥存在哪？会写进配置文件吗**
不会。存在 Windows 凭据管理器（服务名 `sshbox`，条目 `ai:<接入点id>`），`settings.json`
里只有一个 `has_key` 布尔值。点「删密钥」单独清，或删掉整个接入点（密钥一起删）。

**AI 会自己执行命令吗**
不会。生成的命令只**填入**终端，回车由你按；跨标签双击历史命令也会先切回它对应的主机。

**分组顺序能调吗**
能。按住分组标题（左边有 `⠿` 把手）上下拖动即可，顺序会保存到
`hosts.json`。默认只展开第一个分组，点标题可展开 / 收起。

## 卸载

设置 → 应用 → 已安装的应用 → SSHBox → 卸载。
配置和历史数据不会自动删除，如需彻底清理，手动删掉
`%APPDATA%\sshbox\` 和 `%LOCALAPPDATA%\com.z.sshbox\`。
