# 演练台真机验证清单（真实 Linux）

> 目的：把「注入 → 观测 → 清除」全链路在一台**真实 Linux** 上跑通。
> WSL2 内核 5.15.153.1 无 `sch_netem`（实测 `Error: Specified qdisc kind is unknown.`），
> 所以在此之前演练台只能算 demo。**跑通本清单才算产品。**
>
> 未验证项会在文末「已知未验证」里诚实列出，不要当成已测过。

## 0. 环境登记（先记录，出问题好回溯）

| 项 | 命令 | 记录 |
|---|---|---|
| 发行版/内核 | `cat /etc/os-release; uname -r` | |
| tc 版本 | `tc -V` | |
| iproute2 | `ip -V` | |
| 出口网卡 | `ip route show default` | |
| 是否容器 | `systemd-detect-virt` | |
| 内核有无 netem | `modprobe sch_netem && echo ok` | |
| 当前身份 | `id` | |

**判据**：`tc -V` 有输出、`sch_netem` 可加载（或已内置）。二者缺一 → 演练台在这台机器上不可用，
此时应当**在 UI 里如实提示**而不是静默失败。

## 1. 权限路径

| 场景 | 操作 | 预期 |
|---|---|---|
| root 直连 | 用 root 登录 SSHBox | 演练台能直接注入，无提权提示 |
| 非 root 直连 | 用普通用户登录，不切 root | 注入应**失败并明确提示**"需要 root/NET_ADMIN"，不得显示"已注入" |
| 非 root + 终端 `su root` | 普通用户登录 → 在终端里 `su -` 切 root → 回演练台注入 | 注入**应生效**（走 pty，跟随当前身份） |
| 同上，然后清除 | 点清除 | 清除**也应生效**（历史 bug：清除走独立 exec 用登录用户身份 → 失败；已修为可「填入终端（跟随当前身份）」）→ **重点复验** |

## 2. 注入 → 观测 → 清除（每个故障类型各走一遍）

对**默认网关**做（不要拿 `127.0.0.1` 测，回环不受 netem 影响）。

### 2.1 时延
1. 记录基线：终端里 `ping -c 5 <网关>` → RTT 基线 ___ ms
2. 演练台注入时延 200ms（网卡选**出口网卡**，见 §0）
3. 判据 A（命令层）：目标机 `tc qdisc show dev <网卡>` 能看到 `netem delay 200ms`
4. 判据 B（效果层）：`ping -c 5 <网关>` RTT ≈ 400ms（往返）或 +200ms（单向，取决于配置）
5. 监控面板「时延」曲线应上升，**不是** `0 ms` 也不是平线
6. 点清除 → `tc qdisc show dev <网卡>` 无 netem → ping RTT 回落到基线

### 2.2 丢包
1. 注入丢包 10%（用 `-c 10` 以上样本，样本太少百分比会跳）
2. 判据：`ping -c 10 <网关>` 丢包率 ≈ 10%（±2 个包内可接受）
3. 监控面板丢包曲线同步
4. 清除 → 丢包回 0%

### 2.3 闪断
1. 注入闪断（短时断链）
2. 判据：连接**断开一次**后自动重连成功；标签状态点经历 红→黄→绿
3. 清除 → 不再闪断

## 3. 边界与诚实性（这些是历史踩过的坑）

| 检查 | 判据 |
|---|---|
| 注入未生效检测 | 故意选**错误网卡**（如 `lo`）注入 → UI 必须提示"未生效"，不得显示"已注入" |
| 参数钳制 | 输入时延 99999ms / 丢包 200% → 应被钳制或拒绝，不能把非法值发下去 |
| 清除不排队 | 注入进行中立刻点清除 → 清除应立即执行（历史：排在注入后面） |
| 多台同时注入 | 两台不同网卡各注入不同参数 → 各自独立生效，互不覆盖 |
| 采集只读 | 全程目标机 `/tmp`、`/var/tmp` 无新文件（`ls -lt /tmp | head`）；演练台只读 `/proc`、`/sys`、命令输出 |
| 非 root 权限提示 | `hidepid=2` 时进程列表读不到 → UI 应说明原因，不是空白 |

## 4. CentOS / 老版本差异（重点，未验证）

Ubuntu 与 CentOS 的 `tc` 参数/输出格式可能不同，逐项确认：

- `tc qdisc add dev X root netem delay 200ms` 在 CentOS 7（iproute2 4.x）是否接受同样语法
- 删除用 `tc qdisc del dev X root` 还是需要 `handle` 指定
- 网卡命名（`ens33`/`eth0`/`enp0s3`）→ 演练台网卡下拉是否列出了正确选项
- 无 `tc` 时（最小化安装）→ UI 应提示"目标机缺 tc"
